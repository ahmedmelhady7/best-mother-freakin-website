    What You Should Actually Do

    The HTML5-First Priority Stack
    1. Semantic HTML5 first. Use proper elements: <header>, <nav>, <main>, <article>, <section>, <aside>, <footer>.
    2. Native HTML5 features. Use <details> for accordions, <dialog> for modals, <datalist> for autocomplete, <progress> and <meter> for indicators.
    3. Native form validation. Use required, pattern, type="email", min, max, step attributes.
    4. Accessibility built-in. Proper <label> elements, ARIA attributes, semantic structure.
    5. Zero dependencies. No CSS frameworks. No JavaScript libraries. Just HTML5.

    FAQ: Why Pure HTML5?

    Pure HTML5 is accessible. Pure HTML5 is fast. Pure HTML5 works on a 2G connection. Pure HTML5 doesn't discriminate based on hardware, JavaScript support, or browser capabilities.

    Does it look boring?

    Yes! And that's the point. Style is secondary to function. Your browser's default styles are actually quite good and accessible. You can always add CSS later if needed, but start with pure HTML5.

    What about interactive features?

    Many "interactive" features are built into HTML5: <details> for expandable content, <dialog> for modals, native form validation, contenteditable for editing. For more complex interactions, add minimal JavaScript as progressive enhancement.

    Is this really usable?

    Absolutely! This page is fully functional, accessible, keyboard-navigable, and screen-reader friendly. It just uses browser default styles instead of custom CSS. The content and functionality are what matter.
